# NeoSync - Development Notes

Windows tool for the AlphaSmart Neo: connects over USB, switches it into transfer
mode, and downloads/uploads AlphaWord text files. Originally a Windows port of
[AlphaSync](https://github.com/tSoniq/alphasync) (macOS, reference only, not built
here) and cross-checked against [neotools](https://github.com/rbanffy/neotools)
(Linux, reference only).

## Architecture

Three projects:
- **NeoSync.App** - the WinForms UI (Connect/Disconnect/Download/Upload/Quick Sync).
- **NeoSync.Service** (`NeoSyncHelper.exe`) - a Windows service running as LocalSystem.
  All driver install/remove and USB mode-switch operations happen here, since they
  need admin rights and must keep working even if the app itself isn't elevated.
  The app talks to it over a local named pipe (`NeoSyncHelperClient`/`NeoSyncWorker`).
- **NeoSync.Core** - shared protocol/USB code referenced by both.

The installer (Inno Setup, `installer/NeoSync.iss`) creates the service, stages a
pre-signed WinUSB driver package (`installer/driver/*.inf/.cat/.cer`, generated by
`installer/driver/create-driver-package.ps1`), and performs the first mode switch
--- all routed through the same service code path used at runtime, so install-time
setup gets the same self-healing behavior as a normal Connect (see "Driver lifecycle"
below).

There is no separate driver-installation library (libwdi/Zadig) any more -- WinUSB
is installed directly via `pnputil` using our own signed driver package.

## USB / Protocol details

### Device VID/PIDs
- `0x081e / 0xbd04` - HID keyboard mode (default on power-up)
- `0x081e / 0xbd01` - Comms mode (bulk USB, used for file transfer)

### Mode switch sequence
Send 5 USB control transfers to BD04 via WinUSB:
```
bmRequestType = 0x20  (Class | Device | Host->Device)  NOT 0x21 (Interface)
bRequest      = 0x09  (HID SET_REPORT)
wValue        = 0x0200 (Output report type=2, ID=0)
wIndex        = 0x0001 (arbitrary firmware-level tag - BD04 has only ONE real interface)
wLength       = 0x0001
data          = 0xe0, 0xe1, 0xe2, 0xe3, 0xe4  (one byte per transfer)
```
Preceded by a standard `SET_CONFIGURATION` (wValue=1) control transfer.
Confirmed against `neotools` (`device.py` `flip_to_comms_mode()`), which is
authoritative here -- the tSoniq/Mac docs implied `bmRequestType=0x21`
(Class|**Interface**), which is wrong. BD04 has only one real USB interface; there
is no MI_01 to split out via a composite driver (a dead-end explored earlier).
Source: `NeoHidSwitcher.TrySwitchToCommsMode()` in `NeoSync.Core/Usb/`.
Send once, wait for BD01 to enumerate -- do not resend if the transfer succeeded,
the Neo may already be mid-reset, and resending to a disappearing device returns
Win32 error 22 (`ERROR_BAD_COMMAND`) and can disrupt the switch in progress.

### Device discovery (BD01)
`SetupDiGetDeviceInterfaceDetail` returns an empty SymbolicLink for BD01 even when the
device is present (WinUSB doesn't write it until first open). Instead we build the path
directly from the `DeviceClasses` registry key name:

```
HKLM\SYSTEM\CurrentControlSet\Control\DeviceClasses\{3D10B9D7-...}\
  ##?#USB#VID_081E&PID_BD01#<instance>#{3d10b9d7-...}
```
Strip `##?#` -> `\\?\` to get the CreateFile path. See `NeoUsbDiag.FindVidPidInstanceId`
for the generic (non-machine-specific) SetupDi-based instance lookup.

### Bulk pipe enumeration
`WINUSB_PIPE_INFORMATION.PipeType` is a 4-byte `uint` (`USBD_PIPE_TYPE` enum), NOT a byte.
`UsbdPipeTypeBulk = 2` (not 3 - Interrupt is 3). Fixed in `NativeMethods.cs`.

### ASM Protocol
8-byte messages: `[cmd(1)] [payload(6)] [checksum(1)]`
Checksum = sum of bytes 0-6 mod 256. All multi-byte payload values are big-endian.

Key sequences (all from `alphasync/AlphaSync/Driver/ASDevice.cc`):
- **Hello**: write `0x01` (1 byte), read 2 bytes back (version, must be >= 0x0230)
- **Reset**: write `{0x3f, 0xff, 0x00, 0x72, 0x65, 0x73, 0x65, 0x74}` (8 bytes)
- **SwitchApplet**: write `{0x3f, 0x53, 0x77, 0x74, 0x63, 0x68, appletHi, appletLo}`,
  expect back `{0x53, 0x77, 0x69, 0x74, 0x63, 0x68, 0x65, 0x64}` ("Switched")
- **dialogueStart** = Hello + Reset + SwitchApplet(0x0000)
- **dialogueEnd** = Reset()

File reads use a BLOCK_READ loop:
  Send REQUEST_BLOCK_READ -> receive RESPONSE_BLOCK_READ (with blocksize+checksum) -> read blocksize bytes -> repeat

File writes use a BLOCK_WRITE loop:
  Send REQUEST_BLOCK_WRITE (with blocksize+checksum) -> receive RESPONSE_BLOCK_WRITE -> write blocksize bytes -> receive RESPONSE_BLOCK_WRITE_DONE -> repeat

## AlphaWord file format

Source: `alphasync/AlphaSync/Driver/ASAlphaWordFile.cc` - `exportText()` / `importText()`

### Decoding (download)
| Byte | Meaning |
|---|---|
| `0x09` | Tab |
| `0x0d` | End of paragraph -> CRLF |
| `0x81`, `0xa1` | Line-breaking space -> regular space |
| `0x8d`, `0xa3` | Line-breaking tab -> tab |
| `0x8f`, `0xa4`, `0xa7` | Discard (break hints / pad bytes) |
| `0xa8`, `0xa9` | Discard (unknown/display control) |
| `0xad` | Line-breaking hyphen -> `-` |
| `0xb0` | Escape sequence: `{0xb0, code, 0xb0}` -> treat `code` as a raw character |
| `0xa1-0xbf` (other) | Discard |
| `0x80-0xff` (other) | Decode as CP1252 (Windows-1252) |

### Encoding (upload)
- Regular ASCII (0x20-0x7E): stored as-is
- Tab -> `0x09`; Newline/CR -> `0x0d`
- CP1252 chars in `0xa1-0xbf`: wrap in escape `{0xb0, byte, 0xb0}`
- Other CP1252 (0x80-0xa0, 0xc0-0xff): stored as-is
- File padded to minimum 512 bytes with `0xa7` fill bytes
- The Neo regenerates line-breaking hints on first open - we don't insert them

### File size fields
`NeoFileAttributes.MinSize` is a **constant** minimum block allocation (512 bytes on
observed hardware) -- NOT the content size. `AllocSize` is the field that actually
varies per file; a file is empty when `AllocSize <= MinSize`.

### Password field
`NeoFileAttributes.Password` (offset 0x10, 7 chars) is NOT a reliable "is this file
locked" signal. Both AlphaSync (`ASFileNode.mm`) and neotools (`commands.py`) write
the literal placeholder string `"write"` into this field on every file create/write,
because the on-device firmware rejects an empty password at creation time
(`ASDevice.cc`: `if (0 == strlen(attr->password())) return false;`). Real hardware
testing confirmed every file -- locked or not -- carries this same fixed byte pattern.
Do not attempt to surface a "locked" indicator from this field without a genuine
locked-file sample to test against first.

### AlphaWord file count
The applet header's `FileCount` field (offset 0x17) is **0** for AlphaWord even when files exist.
Use `REQUEST_GET_USED_SPACE` (0x1b) with `argument(1,4)=1` to get the real file count:
response `argument(5,2)` = file count.

## Applet header format
Size: `0x84` bytes. Source: `alphasync/AlphaSync/Driver/ASApplet.h`

| Offset | Field | Notes |
|---|---|---|
| 0x00 | Signature (uint32) | Must be `0xc0ffeead` |
| 0x10 | Flags (uint32) | Bit 0 = hidden (system applet) |
| 0x14 | AppletId (uint16) | `0xa000` = AlphaWord |
| 0x17 | FileCount (uint8) | Unreliable for AlphaWord, use GET_USED_SPACE |
| 0x18 | Name (36 bytes) | Null-terminated ASCII |

Known AppletIds: `0xa000` = AlphaWord, `0xa005` = Dictionary, `0x0000` = System.
AlphaWord flag value: `0xff0000ce` (hidden bit NOT set -> shown in default view).
System/font/spell applets have hidden bit set (`flags & 0x01 == 1`).

## Driver lifecycle

### Overview
WinUSB must be installed on two VID/PIDs: BD04 (keyboard mode, needed only to send the
mode-switch control transfers) and BD01 (comms mode, for file transfer). The Neo has no
HID MI_01 interface, so WinUSB on BD04 is mandatory -- keyboard emulation cannot be
preserved while NeoSync's driver is active (see the explanation embedded in
`installer/LICENSE.txt` and the install-time MsgBox in `NeoSync.iss`).

### Setup (`NeoSyncWorker.CmdSetupDrivers`)
1. Trusts the signing cert (`certutil -addstore Root/TrustedPublisher`).
2. Stages both INFs via `pnputil /add-driver`.
3. If BD04 is currently in a bad state (composite/error/other), force-installs immediately.

### Switch (`NeoSyncWorker.CmdSwitch` / `TrySwitchOnce`)
1. Fast path: if BD01 is already present and healthy, done immediately.
2. Self-heals a BD01 that's already switched but stuck in `CM_PROB_FAILED_START`
   (a soft device restart via `Bd04WinUsbCycle.RestartDevice`, not a reinstall) --
   this specifically covers the case where the installer's own driver-setup step
   already switched the Neo and it lands in this transient state before the app's
   first Connect ever runs.
3. Otherwise installs BD04 WinUSB if needed, sends the 5 mode-switch control transfers,
   then polls for BD01 to appear and force-installs its driver the moment it does,
   with the same self-heal retry for transient failures.
4. One attempt per Connect click -- repeated back-to-back install/reset cycles were
   found to progressively wedge the USB port. If it fails, the user is told to
   physically replug the Neo (a real reset) and click Connect again.

### Remove (`NeoDriverInstaller.RemoveBoth` / `RemoveAllMatchingInfs`)
Scans all `C:\Windows\INF\oem*.inf` files for VID_081E&PID_BD04 / VID_081E&PID_BD01
content and deletes every match via `pnputil /delete-driver <inf> /uninstall /force`.
Used by both "Advanced > Repair NeoSync > Remove WinUSB drivers" in the app and by the uninstaller
(`CurUninstallStepChanged` in `NeoSync.iss`) -- removing the driver restores the Neo
to Windows' inbox keyboard driver on next replug.

## Known issues / future work

- **BD01/BD04 transient `CM_PROB_FAILED_START`**: a Windows PnP timing quirk that
  happens periodically regardless of the fixes above; self-heals via device restart,
  may occasionally still need a manual replug. Not fully eliminable, only mitigated.
- **Features not yet implemented**: rename files on device, create new file slots,
  backup all applets (not just AlphaWord -- Quick Sync currently covers AlphaWord
  only), auto-launch on device connect, drag-and-drop upload/download.
- **Diagnostic logging is opt-in**, toggled via Advanced > Enable diagnostic
  logging (also offered as an installer task, checked by default) and backed by
  `DiagnosticsSettings` (`%ProgramData%\NeoSync\diagnostics.flag`), honored by
  both the app and the service. Logs (`%TEMP%\neosync_diag.txt`,
  `%ProgramData%\NeoSync\neosync-debug.log`) record command codes, timing, and
  registry state only, never file content.
- **Untested**: original AlphaSmart Neo (Neo 1) hardware -- everything so far has
  only been exercised against a Neo 2. See git history / chat log for the reasoning
  on why it's expected to work (shared VID/PID and protocol across the product line
  per both reference implementations), but this hasn't been verified on real Neo 1
  hardware.

## Build & release

```powershell
# Full installer build (publishes App + Service, compiles NeoSync.iss)
powershell -ExecutionPolicy Bypass -File installer\build.ps1 -Version "1.0.0"
# Output: installer\Output\NeoSyncSetup.exe
```

Requires Inno Setup 7 (`C:\Program Files\Inno Setup 7\ISCC.exe`) and a pre-signed
driver package in `installer\driver\` (run `installer\driver\create-driver-package.ps1`
once, or whenever the INF content changes, to regenerate + sign it -- needs a code
signing cert; see that script for parameters).

Quick compile-only check without building the installer:
```powershell
dotnet build C:\repos\neosync\NeoSync.slnx -c Release
```

### Versioning
The `-Version` parameter passed to `build.ps1` sets both the installer's `AppVersion`
and the app/service assemblies' own version (via `/p:Version=` on publish), so
"Advanced > About" in the app always matches the installer that shipped it.

### Debugging tips
- `%TEMP%\neosync_diag.txt` (app-side) and `%ProgramData%\NeoSync\neosync-debug.log`
  (service-side) are appended every run with registry polls, pnputil calls, and
  timing -- the first place to look when a client reports a connection issue.
- `pnputil /enum-drivers | findstr /i neosync` shows every currently-staged NeoSync
  driver package on a machine.
- `Get-PnpDevice | Where-Object { $_.InstanceId -like "*VID_081E*" }` shows current
  live device state for both BD04/BD01.
